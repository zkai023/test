A Hybrid AI and RAG System for Football Transfer Rumor Filtering, Fact-Checking, and PR Alerting

--- TABLE 2 ---
Public relations (PR) teams at professional football clubs struggle to monitor thousands of social media transfer rumors daily, which can trigger fan anxiety and locker room instability. Manually tracking every post is impossible, while running expensive Large Language Models (LLMs) on all incoming data is cost-prohibitive. Solving this with a hybrid AI system will drastically reduce operational costs and workload, while instantly alerting clubs to high-risk brand crises.

--- TABLE 3 ---
The target users are the Public Relations (PR), media monitoring, and communication teams of professional football clubs (e.g., English Premier League clubs). The domain is sports public relations, brand protection, and crisis management.

--- TABLE 4 ---
We will implement a Hybrid AI & RAG System (Narrow ML + RAG + Foundation Model). A lightweight Narrow ML classifier will filter out 80% of low-grade rumor noise. For the remaining 20% high-risk rumors, we will use a RAG (Retrieval-Augmented Generation) system to query a local Vector DB. This ensures the Foundation Model generates PR alerts and draft responses strictly grounded in the club's official player contracts and brand guidelines, completely preventing Silent Failure and Confident Hallucination.

--- TABLE 5 ---
We will Build and Own the data pipeline, the local Vector Database (Chroma/FAISS) containing proprietary club contract facts, and the L1 deterministic code assertions to verify retrieved content. We will Rent the LLM’s general reasoning capacity through OpenRouter API. This strategy keeps our core business data and factual rules fully under our control (Own), while outsourcing the heavy language processing (Rent).

--- TABLE 6 ---
The system will use two simple datasets: (1) A test list of 15–20 public transfer rumors copied from social media. (2) A synthetic, AI-generated Markdown document containing 10 fictional player contract profiles and 3 PR response templates to act as our local Vector DB source. This synthetic data is 100% private, safe, and has zero-barrier for acquisition.

--- TABLE 7 ---
Business Metric: Escape Rate (missed high-risk rumors = 0%) and Groundedness Score (percentage of PR outputs that accurately match RAG facts, target = 100%).
Technical Eval Check: L1 Assertions will check that outputs are in valid JSON and contain retrieved player-specific identifiers. An L2 LLM-as-judge will rate the Faithfulness of the generated PR response against the retrieved source documents using a 3-point rubric.

--- TABLE 8 ---
The primary risk is a Silent Failure (specifically a False Negative), where the first-layer lightweight filter incorrectly classifies a genuine, high-risk hostile leak as "low-risk noise," causing the PR team to miss the golden response window. To mitigate this risk for responsible use, we will set a highly conservative classification threshold (biasing toward safety) and implement a simple periodic human-in-the-loop audit for filtered-out posts.

--- TABLE 9 ---
A local Python script that reads 2 synthetic player profiles, chunks and embeds them into a lightweight local Vector DB (e.g., Chroma), and runs a simple query. When a mock transfer rumor is inputted, the script retrieves the relevant player facts, sends them to the OpenRouter API, and prints a grounded, structured JSON response.
